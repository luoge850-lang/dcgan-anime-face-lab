# 06：服务化部署、阶梯压测与内存泄漏审计

## 目标

把 04/05 最终选定的 engine 放进单进程、单 GPU 的本地 HTTP 服务，使用 Locust 阶梯式增加并发，并同步采集 P99、错误率、GPU 显存、GPU 利用率和服务进程 RSS。

## 实验思路

```text
启动服务并加载一个最终 engine
→ health 检查
→ 低并发 warm-up
→ 1、2、4、8、16、32... 阶梯加压
→ 每 5 秒记录 GPU/RSS
→ 每级稳定运行后冷却
→ 重复低/高并发周期验证是否泄漏
```

Locust 必须通过 HTTP 接口压测，不能只在同一 Python 进程内直接调用推理函数，否则无法覆盖请求排队、服务调度和返回序列化。

## 监控字段

- GPU 显存已用/总量/峰值；
- GPU 利用率或 SM 利用率；
- 服务进程 RSS、CPU 和请求数；
- 并发数、阶段编号、时间戳；
- P50/P95/P99、RPS、错误率、超时率。

## 拐点判定

分别记录：

1. 计算饱和拐点：GPU 接近饱和且吞吐量不再增长；
2. 服务稳定性拐点：P99 相对前一级明显跳升或错误率超过预设阈值；
3. 硬崩溃拐点：OOM、TensorRT 执行错误、服务退出或大规模请求失败。

如果测试上限内没有硬崩溃，报告必须写“在最高测试并发 N 内未触发”，不能虚构一个崩溃并发数。

## 规划脚本

- `06A_service.py`：加载 engine、health 和 generate 接口。
- `06B_locustfile.py`：固定请求协议和 Locust 用户行为。
- `06C_monitor_system.py`：每 5 秒采集 NVML 与 psutil 指标。
- `06D_run_staged_load.py`：执行阶梯并发、阶段冷却和日志归档。
- `06E_merge_service_report.py`：生成汇总表、三维图和拐点结论。
